자주 묻는 질문

Devin Security는 무엇인가요?

Devin Security는 코드의 보안 취약점을 찾고, 검증하고, 고칩니다. 정해진 패턴 목록과 코드를 대조하는 대신, 보안 엔지니어처럼 코드를 읽는 Devin 에이전트 팀을 띄웁니다. 데이터가 어떻게 흐르는지, 공격자가 취약한 줄에 실제로 닿을 수 있는지, 작은 문제 여러 개가 합쳐져 실제 공격이 되는지 따져 봅니다.

스캔을 실행하면 실제로 무슨 일이 일어나나요?

스캔은 하위 에이전트 여러 개를 띄우고 조율하는 오케스트레이터 에이전트입니다. 하위 에이전트는 보안 작업을 한 부분씩 맡습니다. 핵심 단계 세 개와 선택 단계 두 개가 있습니다.

(1) 위협 모델링과 매처 생성. 위협 모델은 시스템, 서비스, 네트워크 정책, 데이터 흐름의 지도를 바탕으로 합니다. Devin이 코드와 인프라를 보고 초안을 만들면, Devin이 볼 수 없는 부분은 팀이 바로잡습니다. 이 모델 덕분에 스캔이 좋아지고, 우선순위가 현실에 맞고, 다른 도구의 탐지 결과도 다시 채점할 수 있습니다.

(2) 조사. 배치마다 에이전트 하나씩, 여러 에이전트가 동시에 돌아갑니다. 각 에이전트는 신호 주변의 실제 소스 코드를 읽고 어느 것이 진짜 취약점인지 판단합니다. 깊이는 여기서 나옵니다. 신호는 볼 코드를 가리킬 뿐이고, 에이전트는 그 너머까지 보며 파일을 넘나들어 문제를 추적합니다.

(3) 취합과 분류. 에이전트 하나가 모든 탐지 결과를 모아 중복을 없애고, 담당자로 보이는 사람을 붙이고, 파일을 넘나드는 공격 연쇄를 구성하고, 결과마다 우선순위를 매깁니다.

(4) 런타임 검증(선택). 스캔 프로필에서 켜면 에이전트가 앱을 띄우고 상위 탐지 결과를 안전하게 재현해 실제로 악용 가능한지 확인합니다.

(5) 보고서(선택). 프로필에서 켜면 에이전트가 결과를 공유용 보고서로 정리합니다. 보고서 템플릿은 바꿀 수 있습니다.

조사 에이전트 여러 개를 동시에 돌리기 때문에, 몇 주씩 걸리지 않고도 코드베이스 구석구석에 보안 엔지니어 수준의 깊이를 적용할 수 있습니다.

일반 스캐너와 무엇이 다른가요?

오탐이 적고, 증거가 붙습니다. 모든 후보는 표시되기 전에 도달 가능성과 영향도를 엄격하게 검사받고, (켜져 있다면) 런타임 검증으로 실제 빌드에서 재현됩니다. 팀에 전달되는 건 손으로 분류해야 할 '아마도' 목록이 아니라 증거입니다.

스캐너가 놓치는 종류의 취약점. 에이전트가 단계별로 추론하므로, 로직 결함과 연쇄 공격을 찾습니다. 하나하나는 심각도가 낮은 문제 여러 개가 합쳐져 실제 위협이 되는 경우입니다. 패턴 기반 도구로는 닿지 못하는 영역입니다.

티켓이 아니라 수정까지. 어떤 탐지 결과든 Devin에게 다시 맡겨 정책에 맞는 PR을 열게 할 수 있고, 다음 스캔에서 그 수정이 실제로 문제를 해결했는지 확인합니다.

대규모 적용. 병렬 구조 덕분에 하나의 프로그램으로 많은 저장소를 스캔할 수 있고, 후속 스캔은 바뀐 부분만 봅니다. 그래서 꾸준히 스캔해도 비용 부담이 크지 않습니다.

런타임 검증은 어디서 실행되나요?

Devin은 자기만의 격리된 머신에 앱을 띄우고 그 안에서 탐지 결과를 안전하게 재현합니다. 결과는 확인됨, 오탐, 사람 검토 필요 중 하나로 돌아오며 로그와 스크린샷이 붙습니다.

쓰던 스캐너를 가져와도 되나요?

네. 기존 스캐너에 대한 접근 권한을 Devin에게 주고, 스캐너를 실행하거나 결과를 가져오도록 지시할 수 있습니다. 현재는 프로필 기능에서 프롬프트와 API 연동으로 설정합니다. 그러면 Devin이 검증, 중복 제거, 공격 연쇄 구성, 우선순위 지정, 수정을 돕습니다. 스캔 프로필에는 스캐너별 처리 순서와 지시를 넣어 맞춤 설정할 수 있습니다.

기존 스캐너를 대체하나요?

Devin Security는 더하는 도구입니다. 탐지 범위는 넓을수록 좋습니다. 기존 스캐너가 할 수 있는 것보다 더 많이 찾고 처리하도록 돕습니다. 가치가 확인되면 시간이 지나며 일부 기존 SAST·DAST 워크플로를 대체할 수도 있습니다.

어떤 모델을 쓰나요?

Devin Security는 특정 모델에 묶이지 않습니다. 주요 AI 연구소의 모델과 Cognition 자체 모델을 함께 쓰고, 비용 대비 성능에 맞춰 알아서 골라 씁니다. Deep 모드에서는 최상위 사이버 보안 모델도 씁니다.

스킬을 쓰는 것과는 무엇이 다른가요?

범위가 좁은 보안 작업이라면 Devin 워크플로를 써도 충분합니다. 차이는 구조에 있습니다. 스킬은 프롬프트이고, Devin Security는 에이전트형 map-reduce 구조로 여러 Devin을 조율해 코드베이스 전체를 추론하는 오케스트레이션 계층입니다. 무언가를 믿어도 되는지 알려면 저장소 전체에서 실제로 어떻게 쓰이는지 따져 봐야 하는 경우가 많기 때문입니다. Devin Security는 동적 저장소 분할, 병렬 조사, 완료 관리, 비용을 고려한 배치, 증분 스캔, 리듀서 기반 중복 제거와 우선순위 지정, 결과별 런타임 검증(선택), 스캔 프로필, 그리고 Devin 수정으로 이어지는 탐지 결과 수명주기를 제공합니다.
