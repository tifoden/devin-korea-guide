Devin은 하나의 앱이 아니라 여러 곳에서 쓰는 제품군입니다. 공식 Desktop FAQ는 제품을 Devin Cloud, Devin Desktop, Devin CLI, Devin Review 네 가지로 묶어 설명합니다. 공식 사이트 메뉴는 여기에 Mobile을 더해 사용 환경으로 묶고, Review·Security·Oncall을 기능으로 둡니다.

제품별 페이지

공식 사이트의 Product 메뉴는 사용 환경(Surfaces)으로 Devin Cloud, Devin Desktop, Devin CLI, Mobile을 묶고, Review·Security·Oncall은 기능(Features)으로 따로 둡니다. 제품마다 하는 일과 시작 방법은 각 제품 페이지에서 볼 수 있습니다.

일하는 방식: Ask와 Agent

새 세션에는 두 모드가 있습니다. Ask는 코드를 바꾸지 않고 코드베이스를 탐색하고 계획을 세우는 가벼운 모드이고, Agent는 실제로 작업을 수행하는 모드입니다. 공식 문서는 계획이 완전히 정해져 있지 않다면 Ask로 계획을 만든 뒤 Agent로 실행하라고 권합니다. 모드는 모델과 다른 개념입니다. 모델은 모델 페이지에서 따로 다룹니다.

여러 제품에 걸친 기능

Automations

Slack 메시지, GitHub·GitLab 이벤트, Linear, PagerDuty, 일정, 사용자 정의 웹훅 같은 외부 이벤트에 Devin 세션을 연결합니다. 자동화는 트리거와 액션으로 이뤄지고, 조건과 사전 점검(Preflight)을 덧붙일 수 있습니다. 보안 스캔을 정기적으로 돌릴 때도 씁니다. 자세한 쓰임은 Devin Cloud와 Devin Security에 있습니다.

Ask Devin과 DeepWiki

Ask Devin은 코드베이스에 질문하고 작업을 계획하는 기능이고, DeepWiki는 저장소마다 아키텍처 다이어그램과 문서, 소스 링크를 자동으로 만듭니다. 둘 다 저장소 인덱싱을 바탕으로 동작합니다.

팁

기능은 하나씩 늘리기

처음부터 자동화와 보안 스캔을 모두 켜기보다, Cloud 세션 몇 번으로 지시문 쓰는 감을 익힌 뒤 Review나 Automations를 더하는 편이 결과를 판단하기 쉽습니다.

공식 계정이 소개한 기능, 문서로 다시 보기

Devin 공식 개발자 계정(@devindevelopers)은 X 스레드에서 “20 things you might not know Devin can do”라는 제목으로 기능 20가지를 소개했습니다. 이 절은 그중 관련 있는 기능을 다섯 묶음으로 나누고, 스레드 문장은 짧게 인용만 하고 기능 설명과 제약은 현재 공식 문서로 다시 확인한 내용으로 적었습니다. 스레드는 홍보 성격의 소개이므로, 문서에서 확인되지 않은 표현은 옮기지 않았습니다.

로컬과 클라우드를 잇기

  • Local Hands: 클라우드 세션이 내 컴퓨터에서 셸 명령을 실행하고 파일을 읽고 고칠 수 있게 합니다. 다만 무제한 접근이 아닙니다. 세션 소유자 본인이어야 하고, 같은 계정으로 로그인한 Devin Desktop이나 CLI가 필요하며, 조직의 Local Hands 설정이 켜져 있어야 하고, 도구 호출마다 승인을 받습니다. 화면·키보드·마우스는 제어하지 않습니다. 승인할 사용자가 없는 세션(일정 실행 세션, 자동화, 승인할 사용자가 없는 서비스 사용자 API 세션), 보안 프로필을 쓰는 세션, 네이티브 배포가 꺼진 조직에서는 쓸 수 없고, 아직 점진 배포 중입니다.
  • Handoff: CLI에서 /handoff를 실행하면 대화 맥락과 현재 git 브랜치를 묶어 클라우드 세션으로 넘깁니다. 로컬에서 계획하고 오래 걸리는 구현은 클라우드에 맡기는 식으로 쓸 수 있습니다. Claude Code, Codex 같은 다른 에이전트에서는 오픈소스 Devin Handoff 플러그인으로 넘깁니다.
  • Agent Command Center: Devin Desktop 안에서 로컬 에이전트와 클라우드 Devin 세션을 한 화면에서 관리합니다. ACP(Agent Client Protocol)를 지원하는 서드파티 에이전트도 여기서 실행할 수 있습니다. Free, Pro, Max, Teams에서 쓸 수 있고 Enterprise는 기본적으로 꺼져 있습니다. 외부 ACP 에이전트를 쓰면 과금과 약관은 해당 제공사와의 관계로 넘어갑니다.

실행 환경과 플랫폼

  • macOS VM과 iOS Simulator: 블루프린트에 runs-on: macos를 지정하면 Devin이 Xcode와 iOS Simulator로 iOS·macOS 앱을 빌드하고 테스트하며, TestFlight 업로드도 안내되어 있습니다. Dedicated SaaS 배포는 계정 팀을 통해 켜야 합니다.
  • Android 에뮬레이터: 세션 안의 에뮬레이터에서 Android 앱을 빌드·실행하고, 주요 흐름을 눌러 보며 녹화로 결과를 남길 수 있습니다.
  • CLI 샌드박스: --sandbox로 실행하면 운영체제 수준에서 쓸 수 있는 경로와 네트워크를 제한합니다. 샌드박스를 만들 수 없는 환경에서는 CLI가 샌드박스 없이 실행하지 않고 시작을 거부합니다.

스레드는 특정 기기의 접힌·펼친 화면 테스트까지 언급하지만([@devindevelopers 게시물: macOS and iOS VMs](https://x.Android는 @devindevelopers 게시물: Android Testing, 샌드박스는 @devindevelopers 게시물: Sandboxing에서 소개되었습니다.

검증 근거 남기기

  • 테스트 녹화: PR을 만든 뒤 Devin이 앱을 실행하고 브라우저로 직접 조작하며 화면을 녹화하고, 중요한 순간에 텍스트 주석을 달아 영상으로 보냅니다. 리뷰어가 동작을 빠르게 확인하도록 돕는 근거이며, CI의 자동 테스트를 대신하지는 않습니다.
  • Quick Review: Devin Desktop에서 Devin Local 에이전트가 만든 로컬 변경을 별도 에이전트가 다시 검토해, 커밋하기 전에 편집기 안에 의견을 보여 줍니다. 가격은 요금제에 따라 다릅니다.
  • Since last seen 보기: Desktop 변경 기록(changelog)에 따르면 로컬 세션의 Changes 탭에 파일별 diff와 “Since last seen” 범위가 추가되어, 마지막으로 본 뒤 바뀐 부분만 볼 수 있습니다.

반복할수록 팀에 맞춰지기

  • Memory: 선호, 교정, 프로젝트에서 배운 점을 노트로 저장해 다음 세션에 이어 씁니다. 메모리는 조직 안에서도 개인 단위라 팀원과 공유되지 않습니다.
  • Skills: 저장소의 .agents/skills/<이름>/SKILL.md 파일이나 Customize 페이지로 테스트, 배포, 리뷰 같은 반복 절차를 가르칩니다. 팀이 함께 쓰는 절차는 메모리가 아니라 스킬로 남기는 편이 맞습니다.
  • 환경 스냅샷: Devin이 저장소를 보고 블루프린트를 제안하면, 사람이 검토·승인한 뒤 빌드가 스냅샷을 만듭니다. 이후 세션은 저장소, 도구, 의존성, 환경 변수가 준비된 그 스냅샷에서 시작합니다. 비밀값은 Secrets에 저장합니다.

개발 수명주기 전반으로 넓히기

  • Code Scans: 작성창에 /scan과 찾고 싶은 내용을 적고 저장소를 지정하면, 성능, 테스트 커버리지, 죽은 코드, 접근성 같은 문제를 찾아 결과(findings)를 내고 PR로 고칠 수 있습니다. 완료된 스캔은 새 커밋만 다시 스캔할 수 있고, Automations로 일정 실행도 됩니다. ‘Use code scans’ 권한이 필요합니다.
  • 보안 수정: Security 2.0에서 찾은 취약점을 Devin에게 배정해 수정을 맡깁니다. 조직의 보안 스캔 접근 권한과 역할 권한이 필요합니다.
  • Dynamic Workflows: Devin이 결정적인 Python 스크립트를 작성해 여러 Devin 세션에 일을 나누고 결과를 합칩니다. 문서는 판단이 필요한 독립 단위가 대략 다섯 개 이상일 때 적합하고, 그보다 작으면 일반 세션을 권합니다.

팁

홍보 문장과 문서 확인을 구분하기

스레드의 한 줄 소개는 기능의 존재를 알리는 데 쓰고, 실제 도입 판단은 권한·플랜·배포 상태가 적힌 공식 문서로 하는 편이 안전합니다.

팀·조직으로 도입할 때 확인할 것

개인이 써 보는 단계를 넘어 회사 코드에 연결하려면 기능보다 먼저 데이터 처리, 배포 방식, 접근 관리를 확인해야 합니다.

데이터와 지적재산

  • 암호화: 데이터는 전송 중과 저장 시 모두 암호화한다고 적혀 있습니다(“encrypted in transit and at rest”).
  • 학습 사용: 기본적으로 고객 데이터와 코드로 모델을 학습하지 않는다고 밝힙니다(“By default, Cognition does not train its models on customer data or code.”). ‘기본적으로’라는 조건이 붙어 있다는 점을 같이 읽어야 합니다.
  • 보존 기간: Devin이 처리한 데이터는 별도 합의가 없으면 고객 관계가 유지되는 동안만 보존합니다. 다만 피드백과 사용자 상호작용 데이터는 Cognition이 필요하다고 판단하는 만큼 보존할 수 있다고 적혀 있습니다.
  • 결과물의 권리: Devin이 만든 코드와 작업물은 고객의 지적재산이고 상업적으로 쓸 수 있습니다. 단, 그 결과물로 경쟁 제품을 만들거나 역설계하려는 모델을 학습시키는 것은 금지됩니다.
  • 인증: Cognition은 2024년 9월부터 SOC 2 Type II 인증을 유지하고 있다고 밝힙니다.

공식 홈페이지에는 “Zero data retention enforced with model providers”, “Every session runs in its own VM”이라는 문구도 있습니다. 세부 조건은 계약서 조항으로 확인하세요.

배포 방식

Devin은 두 부분으로 나뉩니다. 판단을 맡는 Brain은 항상 Cognition 클라우드에 있고, 코드를 실행하는 작업 환경인 Devbox의 위치는 배포 방식에 따라 달라집니다.

배포 방식 Devbox 위치 내부망 연결 맞는 조직
Enterprise Cloud Cognition의 멀티테넌트 클라우드. 세션마다 격리된 머신 공개망 또는 IP 허용 목록 저장소와 도구가 공개망이나 IP 허용 목록으로 열려 있는 조직
Customer Dedicated Deployment 고객 전용 단일 테넌트 VPC AWS PrivateLink 또는 IPSec 터널 IP 허용 목록을 쓸 수 없는 사설망 자원이 있는 조직

어느 방식이든 Brain은 Cognition 클라우드에 남습니다. 코드 실행 위치만 바뀐다는 점을 보안 검토 자료에 정확히 적어야 합니다.

접근과 사용량 관리 (Enterprise)

  • 로그인과 계정 관리: SAML·OIDC SSO, SCIM 프로비저닝, IdP 그룹 연동을 지원합니다.
  • 역할: 조직 수준과 계정 수준의 두 단계 역할 체계가 있고, 권한을 골라 만든 커스텀 역할을 사용자나 IdP 그룹에 배정할 수 있습니다.
  • 접속 위치 제한: IP 접근 목록을 설정하면 허용한 IP 대역에서만 웹 앱과 API에 접근할 수 있고, 그 밖의 API 요청은 401로 거부됩니다.
  • 사용량 한도: 여러 조직이 함께 쓰는 풀에는 Budget을, 구성원 한 명에게는 User limit을 걸 수 있습니다. Desktop·CLI의 로컬 사용량과 클라우드 세션 사용량이 같은 한도에 합산되고, 한도에 닿으면 모든 사용 환경에서 새 작업이 막힙니다.
  • 로컬 도구 정책: Enterprise 소개 페이지는 Desktop과 CLI에서 모델, MCP 서버, 명령의 허용 목록을 전사 기준으로 정하고 조직별로 덮어쓸 수 있다고 설명합니다. 세션, 설정, 작업 기록은 감사 로그로 남고 내보내기와 API를 지원한다고 적혀 있습니다.

작업 맥락 연결

Devin은 MCP로 외부 도구와 데이터에 연결합니다. 공식 문서는 Sentry·Datadog 로그 조사, 데이터베이스 조회, Linear 티켓이나 Notion 문서 작성 같은 쓰임을 예로 들고, stdio·SSE·HTTP 세 가지 전송 방식을 지원한다고 적습니다. Slack이나 Teams에서 @Devin을 태그하면 그 대화에서 바로 세션을 시작하고, 진행 상황도 같은 스레드에 답합니다.
